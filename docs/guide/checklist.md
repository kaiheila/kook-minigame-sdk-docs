# 接入检查

上线前，在支持小游戏的 KOOK 客户端中验证完整接入流程，覆盖游戏页面、游戏后端与客户端之间的交互。

## 启动与登录

- 启动绑定来自可信注入链路，host origin 精确匹配，切换实例后不复用旧客户端。
- 未授权时游戏可以打开并完成 `ready()`；读取到的可申请 scope 不被当成已授权。
- 用户主动发起授权；取消后保留可用页面；再次发起创建新登录事务。
- 后端校验 `state`，完成一次性换码，凭据留在后端，游戏建立自己的登录态。
- 如依赖可信游戏上下文，已确认平台接口、scope 和校验规则。
- 游戏真实可用后上报加载结果，登录或资源失败使用约定原因码。

## 多人和原生界面

- 双账号验证邀请发送、接收、进入正确游戏房间；区分 `roomId` 与 `instanceId`。
- 只申请必要 scope；基础授权用户没有额外候选列表读取权限。
- 分页不混用 cursor，名单变化后刷新，临时身份不被用作账号凭证。
- 授权、邀请和官方服务器弹窗互斥，取消、后台状态和频控都能正确处理。

## 中断和结束

- 覆盖撤销权限、实例失效、跨端接管、宿主关闭和游戏销毁。
- 断线时不继续使用旧授权或名单；恢复后重新 `ready()` 并读取宿主状态。
- 连接恢复不会重复发送邀请、重复授权或重复提交旧 code。
- 清理监听、待处理请求和游戏自身渲染循环。

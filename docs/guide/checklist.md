# 接入检查

上线前，在支持小游戏的 KOOK 客户端中验证完整接入流程，覆盖游戏页面、游戏后端与客户端之间的交互。

## 启动与登录

- 游戏直接创建 SDK 并 ready，已移除旧的消息监听、重投及启动绑定缓存；在 KOOK 页面初始化较晚时仍能就绪。
- 正式环境可省略参数；测试环境的 `allowedHostOrigins` 与默认来源合并、去重，不从 URL 或消息推导。传入列表非空且最多 16 项，启动超时和错误配置有明确提示。
- 配置仅含测试来源时，也验证打包 PC 的 `https://www.kookapp.cn` 父页面能完成 ready；其他窗口和未获准来源仍被拒绝。完整显式绑定仍仅使用其 `hostOrigin`。
- 未授权时游戏可以打开并完成 `ready()`；读取到的可申请 scope 不被当成已授权。
- 用户主动发起授权；取消后保留可用页面；再次发起创建新登录事务。
- 后端校验 `state`，完成一次性换码，凭据留在后端，游戏建立自己的登录态。
- 授权签发与换码回调完全一致，目标宿主是否允许自定义回调已经确认，不仅检查 SDK 参数格式。
- 第三方 Cookie 完全不可用时，开始／完成／取消登录仍绑定同一浏览器事务；迟到成功不会恢复已注销的游戏会话。
- 游戏真实可用后上报加载结果，登录或资源失败使用约定原因码。

## 多人和原生界面

- 双账号验证频道不带 roomId 打开频道游戏、显式 roomId 指向固定房间；核对目标宿主是否已接入频道分流。
- 复制链接成功且发送人数为零、正常取消、部分失败和结果未知分别展示，不误报对方已入房。
- 只申请必要 scope；候选列表读取同时检查 `get_user_info` 和对应 capability，并处理宿主拒绝。
- `availableScopes` 为空或过时不被用来硬性拒绝授权申请；实际范围由宿主／服务端判断。
- 分页不混用 cursor，名单变化后刷新，临时身份不被用作账号凭证。
- 授权、邀请和官方服务器弹窗互斥，取消、后台状态和频控都能正确处理。

## 外链和全屏（按需）

- SDK 版本固定为 1.3.1，分别检查 `ui.openExternalLink`、`ui.requestFullscreen` capability；缺少能力时禁用或隐藏入口。
- 外链只提交完整 HTTP/HTTPS 地址，保留 query 和片段；非法协议、凭据或额外选项明确拒绝，不回退为游戏自行打开。
- 覆盖宿主外链的直接跳转、风险拦截和提示继续；成功提交不被展示为目标已加载，当前游戏页面保持原地址。
- 全屏由真实用户点击触发，调用前没有网络或定时器等待；整个当前宿主游戏承载全屏，重复请求不取消，Esc 或宿主按钮正常恢复。
- 验证内嵌、小窗和独立窗口；全屏不重载游戏或影响其他承载。浏览器拒绝、后台、宿主弹框占用及连接恢复时有明确提示，不自动重放操作。

## 上下文玩法（按需）

- 基础身份登录独立完成；只在需要频道大厅或邀请核验时申请 `mini_game.context`，由后端查询。
- 校验游戏、实例、状态和嵌套 room 来源；`room_source=instance` 的回退值不当成游戏房间号。
- 区分实例创建／归属空间、用户打开位置和消息投递位置，准入由游戏后端执行。
- 无权限、满房、失效或查询失败保留已完成的基本登录，不用前端自报参数补齐可信结果。

## 中断和结束

- 使用退出按钮时检查 `lifecycle.leave` capability，先清理游戏房间／存档，再调用离开接口；确认平台参与和当前游戏承载结束。
- 离开失败可重试，连续点击不重复提交；没有该能力的旧客户端有明确降级提示。`destroy()` 不被当作平台退出成功。
- 覆盖撤销权限、实例失效、跨端接管、宿主关闭和游戏销毁。
- 断线时不继续使用旧授权或名单；恢复后重新 `ready()` 并读取宿主状态。
- 连接恢复不会重复发送邀请、重复授权、重复提交旧 code 或重放离开请求。
- 清理监听、待处理请求和游戏自身渲染循环。

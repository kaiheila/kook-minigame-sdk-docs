# 游戏后端登录

需要账号、存档或成绩时，调用 SDK 获取授权码，由游戏后端校验、换码并建立会话。

## 标识与配置

| 标识                            | 来源及用途                                           |
| ------------------------------- | ---------------------------------------------------- |
| `gameCode`                      | 平台小游戏编号；不要推断等于 OAuth client ID         |
| OAuth `client_id/client_secret` | 应用凭据，secret 仅后端保存                          |
| `instanceId`                    | KOOK 承载实例，与游戏房间不是同一个对象              |
| 游戏 `roomId`                   | 游戏后端定义的房间目标及准入对象                     |
| 游戏会话                        | 游戏自己的 Cookie／短期内存会话，与 OAuth token 分开 |

游戏前端提交的实例、频道或房间参数只作为查询选择器或目标提示。用户身份以服务端取得的数据为准，房间准入由游戏后端执行。按需读取实例与频道关系见[上下文接口](./context.md)。

## OAuth 回调与换码

游戏后端配置 `redirect_uri=https://www.kookapp.cn/oauth/mini-game/callback`，前端 `session.get()` 省略 `redirectUri` 即可使用宿主默认值。授权和换码值必须一致；如需自定义回调，先确认目标环境支持并完成应用登记。

游戏后端向配置的 KOOK 服务 origin 发起表单编码请求：

```http
POST /api/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&client_id=...&client_secret=...&redirect_uri=...&code=...
```

使用返回的 Bearer `access_token` 调用 `GET /api/v3/user/me`，取得可信用户身份。token 的 `expires_in` 是秒数；SDK 授权码结果的 `expiresAt` 是 Unix 毫秒，不能混用。用户接口字段及应用开放标识以目标平台接口定义为准，不使用 SDK 候选用户的临时 ID 建号。

应用凭据与 token 保存在游戏后端，生产请求使用 HTTPS；需要实例或邀请关系时继续[查询上下文](./context.md)。

## 游戏登录事务与浏览器会话

游戏 API 路径可以自定义，至少实现以下语义：

| 操作         | 行为                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 开始登录     | 生成至少 128 bit 随机 state（16–256 字符，无空白及控制字符），绑定浏览器、应用、登录事务，设置有效期 |
| 完成登录     | 校验绑定、state、有效期及一次性消费，再换码、读可信用户、建立游戏会话                                |
| 取消登录     | 幂等作废该事务，并精确撤销它已经创建的游戏会话；不误删更新的登录                                     |
| 退出游戏账号 | 撤销游戏自己的会话；不假定等于退出 KOOK 实例或撤销 OAuth                                             |

跨站 iframe 的第三方 Cookie 可能完全不可用。Cookie 方案按部署评估 `Secure/HttpOnly/SameSite=None/Partitioned`；同时准备以随机客户端 nonce 绑定事务、仅驻留当前页面内存的短期游戏会话方案。开始、完成、取消都要核对同一绑定及请求来源。nonce 不是 KOOK token；无效 Bearer 不能降级使用另一个 Cookie 账号。

登录期间核对 SDK 连接 `epoch` 和游戏自己的登录代次。等待 code 或后端响应时若退出、切号、撤销或绑定变化，丢弃迟到结果并取消该事务。只在前端抛错不能撤销后端已经创建的会话，取消接口也要覆盖这一情况；会话写入和取消需由后端协调。

## 取消与重试

`cancelled` 为正常结果，不换码、不循环自动弹框；用户再次发起时创建新事务。一次性授权码不能反复提交；换码超时不代表没有执行，后端按平台协议核对结果。基础登录成功后，[上下文查询](./context.md)失败只阻止依赖它的玩法，不应把已经登录的账号一并清掉。

游戏后端自行维护账号映射与会话续期；日志仅保留调用阶段、非敏感关联标识和错误码。

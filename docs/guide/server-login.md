# 游戏后端登录

游戏后端负责把 KOOK 授权结果转换成游戏自己的可信登录态。SDK 只传递授权码，不接收游戏后端换出的 OAuth token。

## 后端需要完成的步骤

1. 创建不可预测的 `state`，与当前浏览器的登录事务绑定，设置短有效期和一次性消费规则。
2. 收到前端的成功结果后，验证事务仍有效、`state` 匹配、请求来自正确游戏会话。
3. 通过平台约定的 OAuth token 接口交换授权码。应用密钥、access token、refresh token 只在后端保管。
4. 使用平台服务端接口取得可信用户身份；需要游戏上下文时再调用相应平台接口。
5. 校验响应与本游戏、当前用户和业务上下文一致，建立游戏账号映射及自己的登录会话。
6. 向浏览器返回游戏需要的展示信息，或通过安全 Cookie 建立会话。不要返回 KOOK OAuth 凭据。

浏览器上送的 `gameCode`、`instanceId`、`roomId` 只能作为提示，不能单独作为用户身份、实例归属或游戏房间访问权限的凭证。

## 平台接口与配置

本 SDK 文档描述前端接入契约。OAuth 换码地址、应用凭据与回调配置由平台对接方提供。

**获取可信游戏上下文的服务端接口及对应 scope 尚待最终对接确认。** 当前 SDK 的公开 `Scope` 类型只含 `profile.basic`、`friends.dms.read`、`channel.members.read`。不要自行假设上下文字段位于用户信息接口，也不要使用未确认的 scope 名称。

如果游戏必须依赖该上下文才能建立登录态，应把这项接口确认作为联调前置条件。纯展示可使用 `ready()` 的环境提示；涉及权限判断必须回到后端可信数据。

## 重试与凭据

授权码是短期、一次性数据。换码结果不明确时由后端按平台协议处理幂等与查询，不要让前端反复提交旧码。需要重新授权时创建新的登录事务。

不要把 code、token、应用密钥写入 URL、埋点或可公开日志。日志记录业务错误码、请求关联标识和阶段即可。前端显示用户信息时使用游戏后端确认的数据。

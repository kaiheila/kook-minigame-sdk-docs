# 启动与授权时序

游戏页面在 OAuth 授权之前加载。KOOK 的启动前校验与 OAuth 用户授权是两个阶段：实名认证及成年校验由平台在启动前完成，游戏进入后再按需请求用户数据权限。

## 主流程

![启动游戏、ready、按需授权以及游戏后端换码的时序](/sequence.svg)

[打开可放大的矢量时序图](/sequence.svg)

图示为需要身份的玩法；欢迎页或游客体验已可用时，加载成功可以先于可选 OAuth 登录上报。

1. 用户在 KOOK 打开游戏；KOOK 完成启动资格校验并创建、维护实例。
2. KOOK 加载游戏页面，向 iframe 投递 `KOOK_MINI_GAME_BOOTSTRAP`。游戏校验 parent Window、精确 HTTPS origin 和字段；监听晚于 load 时通过 `KOOK_MINI_GAME_BOOTSTRAP_REQUEST` 请求重投，然后创建 SDK 并调用 `ready()`。代码见[快速开始](./quick-start.md#接收宿主启动绑定)。
3. `ready()` 返回实例、环境、能力和 `availableScopes`。游戏可以展示静态内容或无需身份的玩法。
4. 游戏需要用户身份时，向自己的后端创建带随机 `state` 的登录事务，然后从登录交互调用 `session.get({ state, scopes, redirectUri? })`，回调须与换码配置一致。
5. KOOK 按需展示 OAuth 权限弹窗。已有有效同意时可能直接返回；取消则返回 `status: 'cancelled'`，页面继续运行。
6. 同意后，SDK 得到短期授权码与本次有效 scope。游戏将结果提交给自己的后端。
7. 游戏后端校验事务与 `state`，向平台交换授权码，获取可信用户身份，建立游戏自己的登录态。
8. 游戏进入已登录体验；需要频道大厅或邀请核验时，再由后端[按需查询上下文](./context.md)。加载成功在内容实际可用时上报，欢迎页或游客玩法可在授权前上报，不必统一等待登录。**没有 `authenticate()` 环节。**

授权码的 `expiresAt` 只说明何时必须完成换码，不是 SDK 权限的有效期，也不是游戏登录态的有效期。

## 三种状态要分开

| 观察值                                       | 意义                                             | 不代表什么                       |
| -------------------------------------------- | ------------------------------------------------ | -------------------------------- |
| `ready().availableScopes`                    | 宿主观察到的可申请范围，仅供提示，可能为空或过时 | 用户已同意，或请求只能是它的子集 |
| `session.get()` 成功 / `auth.onStateChanged` | 宿主确认的当前 SDK 授权                          | 游戏后端已经登录成功             |
| 游戏后端自己的会话                           | 游戏业务身份和登录状态                           | KOOK 权限永远有效                |

调用 `session.get()` 时，默认只申请 `get_user_info`。显式 `scopes` 可以只包含游戏需要的其他权限，不要求附带 `get_user_info`，也不要求是 `availableScopes` 的子集。SDK 只检查 OAuth scope token 格式及非空、重复值，实际范围由宿主／服务端判断。`profile.basic` 兼容映射为 `get_user_info`，其他合法名称原样交由平台处理。

## 取消、失败与撤销

- 取消：返回 `cancelled`；不发给后端换码，不强制关闭游戏，也不清除已有授权。
- 换码或游戏登录失败：游戏自行展示重试入口。已取得的 SDK 授权与游戏后端登录失败分别处理。
- 退出或连接变化时迟到的成功响应：丢弃前端结果，并让后端幂等取消该事务、撤销它已经创建的游戏会话，避免旧登录恢复；不能只做前端 epoch 检查。
- 权限撤销：宿主发出 `revoked`，当前启动绑定终止，受保护请求和订阅停止。引导用户从 KOOK 重新打开游戏。
- 连接恢复：重新调用 `ready()`，根据宿主的新授权快照决定是否需要再次请求授权。不要自动重复提交旧授权码或重放弹窗请求。

## 静态游戏

不需要身份或用户数据的游戏可以只完成 `ready()` 和加载上报。实例生命周期仍由 KOOK 客户端维护，不能把是否调用 OAuth 当作实例是否存在的依据。

平台原生邀请和官方服务器弹窗可以在就绪后调用，是否显示由宿主按当前绑定、用户操作和平台权限决定。读取用户相关数据仍需要 `get_user_info` 授权及对应 capability。
